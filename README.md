# core--terraform-modules

OpenTofu modules of the Azure sandbox of `cokeSchlumpf`: naming and location helpers, the properties of the sandbox, and the modules that build and deploy containerized apps into it. The sandbox itself (`10--sandbox`) lives in the private repository `core--platform`.

| Module | What it does |
| --- | --- |
| `functions/` | Naming, location and sandbox property helpers, no resources (see [functions/README.md](functions/README.md)) |
| `container_image/` | Builds a container image locally with Podman |
| `sandbox_image/` | Pushes a local image to the sandbox registry |
| `sandbox_database/` | Serverless SQL database on the sandbox SQL server |
| `sandbox_storage/` | Per-app storage account |
| `sandbox_app/` | End-to-end app deployment: build, push, App Service (see [sandbox_app/README.md](sandbox_app/README.md)) |

## Usage

Reference a module from GitHub on its major version branch:

```hcl
module "app" {
  source   = "git::https://github.com/cokeSchlumpf/core--terraform-modules.git//sandbox_app?ref=versions/1"
  app_name = "my-app"
}
```

`versions/1` always points to the latest `1.x` release: fixes and features arrive with the next `tofu init -upgrade`, breaking changes need a new major version. Pin a tag (`?ref=v1.0.0`) for a fully reproducible deployment.

## Sandbox properties

`functions/sandbox_properties/locals.tf` is generated by `10--sandbox` (in `core--platform`), which writes it into a local clone of this repository next to `core--platform`. Don't edit it by hand: after an apply of `10--sandbox` changes it, commit it here through a pull request (`fix: update the sandbox properties`).

## Development

Changes go through pull requests with a conventional commit title, squash-merged; release-please derives the version and the changelog from them. The check runs `tofu fmt -check -recursive` and `tofu validate` on every module:

```bash
tofu fmt -recursive
tofu -chdir=sandbox_app init -backend=false && tofu -chdir=sandbox_app validate
```
